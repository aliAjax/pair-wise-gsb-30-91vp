# 油品配送 · 司机当班排程

- 行业：石油
- 技术栈：Vue3、Vite、TypeScript、Pinia、Element Plus
- 启动：`npm install && npm run dev`
- 构建：`npm run build`

## 解决的问题

配送员换班后，调度员不再按纸面顺序盲目派单。每条待发单必须指定**当班司机、发车时间、预计用时**，排程引擎自动把关：

1. **时段不重叠**：同一司机的驾驶任务区间不能相交（含跨天任务）。
2. **连续驾驶 4 小时强制休息 30 分钟**：自上次不少于 30 分钟的休息后累计驾驶即将达到 240 分钟时，引擎会在上一趟结束后插入一个 30 分钟强制休息；相邻任务天然间隔 ≥ 30 分钟即视为已休息、累计清零。任务若压进应休息的时段，派单不予通过。
3. **改派留痕**：改派时释放原占用时段，并记录改派原因、原司机、原发时间与**旧完成时间**。
4. **未通过即待安排**：校验不通过的单不会占用时段，留在「待安排区」并展示失败原因和最早可用建议时间，可修改后重新提交。
5. **本地持久化**：占用时段、休息安排、待安排单、改派历史均保存在 `localStorage`（key：`hxwlfront-19-driver-schedule-v1`），重开浏览器原样恢复。

## 分层结构

| 层 | 文件 | 职责 |
| --- | --- | --- |
| 司机资料 | `src/data/drivers.ts` | 当班司机、车牌、班次，换班独立维护 |
| 排程判断 | `src/scheduler.ts` | 纯函数引擎：重叠校验、4 小时/30 分休息推导、单日时间轴，不依赖 Vue 与存储 |
| 本地保存 | `src/storage.ts` | localStorage 读写与版本兜底，不含任何业务规则 |
| 状态编排 | `src/store.ts` | Pinia store，串联三层；派单/改派/释放/状态流转 |
| 界面 | `src/App.vue`、`src/components/` | 24 小时司机泳道时间轴（任务块 + 斜纹休息块）、待安排区、派单/改派弹窗 |

休息区间是引擎的**推导产物**而非手工录入，因此不会出现录入的休息与任务自相矛盾的情况。
